## 📌 기능 요구 사항

간단한 로또 발매기를 구현한다.

### ✅ 기본 규칙

- 로또 번호의 숫자 범위는 **1~45**까지이다.
- 1개의 로또를 발행할 때 **중복되지 않는 6개의 숫자**를 뽑는다.
- 당첨 번호 추첨 시 **중복되지 않는 6개의 번호와 보너스 번호 1개**를 뽑는다.
- 로또 1장의 가격은 **1,000원**이다.

---

## 💰 당첨 기준 및 상금

| 등수 | 당첨 기준                   | 상금            |
| ---- | --------------------------- | --------------- |
| 1등  | 6개 번호 일치               | 2,000,000,000원 |
| 2등  | 5개 번호 + 보너스 번호 일치 | 30,000,000원    |
| 3등  | 5개 번호 일치               | 1,500,000원     |
| 4등  | 4개 번호 일치               | 50,000원        |
| 5등  | 3개 번호 일치               | 5,000원         |

## 🧮 프로그램 동작 흐름

1. **로또 구입 금액**을 입력받는다.

   - 금액은 1,000원 단위로 입력해야 하며,  
     1,000원으로 나누어 떨어지지 않는 경우 예외 처리한다.

2. **입력한 금액만큼 로또를 발행**한다.

   - 각 로또 번호는 오름차순으로 정렬하여 출력한다.

3. **당첨 번호**(6개)와 **보너스 번호**(1개)를 입력받는다.

4. **구매한 로또 번호**와 **당첨 번호**를 비교한다.

5. **당첨 내역 및 수익률**을 출력한다.

   - 수익률은 소수점 둘째 자리에서 반올림한다.  
     (예: `100.0%`, `51.5%`, `1,000,000.0%`)

6. **잘못된 입력값**이 들어올 경우
   - `[ERROR]`로 시작하는 메시지를 출력하고  
     해당 단계부터 다시 입력을 받는다.

## ✨ 기능 목록 (Feature List)

### 1. 로또 구입금액 입력 기능

- 로또 구입 입력을 입력받는다.

  - "구입금액을 입력해 주세요." 문자열을 출력한다.
  - 사용자로부터 입력을 받는다.
    - **[예외처리1]** 숫자가 아닌 다른 타입(문자열, 불린 등)이나 소수, 음수일 경우
    - **[예외처리2]** 1000원으로 나누어떨어지지 않을 경우
    - **[예외처리3]** 입력값이 비어있을 경우

### 2. 로또 발매기 구현

- 구입 가격에서 1000원을 나눈 값만큼 로또를 발행한다
- 1개의 로또를 발행할 때 중복되지 않는 6개의 숫자를 뽑는다.

### 3. 로또 추첨 구현

- 당첨 번호와 보너스 번호를 사용자로부터 입력받는다.
- 당첨번호는 콤마(,)로 기준으로 분리한다.
  - **[예외처리1]** 숫자가 아닌 다른 타입으로 입력받을 경우(문자열, 불린 등)
  - **[예외처리2]** 쉼표(,)가 없을 경우
  - **[예외처리3]** 당첨번호를 6개 입력 다 하지 않았을 경우
  - **[예외처리4]** 보너스번호를 1개 이상 입력 했을 경우
  - **[예외처리5]** 번호가 1~45 사이가 아닐 경우
  - **[예외처리6]** 중복된 번호가 입력되었을 경우

### 4. 결과 출력

- 발행한 로또 수량 및 번호를 출력한다.
  - 로또 번호는 오름차순으로 정렬하여 보여준다.
- 당첨 내역을 출력한다.
- 수익률을 출력한다.
  - 소수점 둘째자리에서 반올림한다.

### 5. 테스트 기능

- 각 기능별 유효성 검증을 위한 테스트 코드를 작성한다.
- `Jest`를 사용하여 기능들이 정상적으로 동작하는지 확인한다.

### 환경 및 실행 조건

- [ ] Node.js `22.19.0` 버전에서 실행 가능해야 한다. (명령어: node --version -> nvm use 22.19.0)
- [ ] 외부 라이브러리를 사용하지 않는다.
- [ ] 프로그램 종료 시 `process.exit()`를 호출하지 않는다.
- [ ] 프로그래밍 요구 사항에서 달리 명시하지 않는 한 파일, 패키지 등의 이름을 바꾸거나 이동하지 않는다.
- [ ] 자바스크립트 코드 컨벤션을 지키면서 프로그래밍한다.

---

### 코드 스타일 가이드

- [ ] **Javascript Style Guide**를 따른다.
- [ ] **영문 이외의 언어**를 코드 내에서 사용하지 않는다.
- [ ] 클래스, 메서드, 함수 이름에 **특수문자**를 사용하지 않는다.
  - 예시: ❌ `function $handle()` → ✅ `function handle()`
- [ ] 상수명은 **SNAKE_CASE**로 작성한다.
  - 예시: `const FIREFOX`
- [ ] **indent depth(들여쓰기)**는 최대 2까지만 허용한다. (3 이상 금지)
- [ ] **3항 연산자(`?:`)**를 사용하지 않는다.
- [ ] 함수(또는 메서드)는 **한 가지 일만 하도록 작게 분리**한다. (함수의 길이가 15이상을 넘어가지 않도록 구현)
- [ ] else문을 지양한다

### Lotto 클래스

## 👩🏻‍💻 소감문

**[ 이번 주차에서의 새로운 시도 2가지 ]**

**1. 설계 단계에서의 변화**

처음으로 시퀀스 다이어그램 형태의 구조를 만들어봤습니다.
 이번 과제에서는 코드를 작성하기 전에 다이어그램을 통해 구조를 구상하는 데 더 많은 시간을 들였습니다.

이렇게 한 이유는 이전 과제들의 경험 때문이었습니다.

1주차에는 폴더 구조 없이 App 파일에 모든 코드를 작성했습니다.

2주차에는 MVC 패턴을 적용하여 폴더 구조를 나누고, 이틀에 걸쳐 리팩토링을 진행했습니다.

이 과정을 통해 MVC 패턴과 파일 분리를 익혔지만, 코드를 작성하면서 동시에 구조를 만들어가다 보니
전체적인 일관성이 부족하고 코드가 중구난방해지는 아쉬움이 있었습니다.
그래서 이번에는 코드 작성보다 서비스 흐름 설계에 집중해야겠다고 생각했습니다.

먼저, 노트에 직접 그림을 그려봤습니다. 그리고 Mermaid 문법으로 시퀀스 다이어그램 형태의 전체 흐름을 완성한 후 코드를 작성했습니다.

그 결과, 이후에 파일 구조나 이름을 변경하기 위한 리팩토링 시간을 줄일 수 있었고,
처음부터 보다 체계적이고 정돈된 구조로 코드를 작성할 수 있었습니다.

**2. TDD 방식의 도입**

이번 과제에서는 기존과는 다른 TDD(Test-Driven Development) 방식을 적용했습니다.
이전 과제에서는 일반적인 개발 과정을 따랐는데,
나중에 테스트 코드를 작성할 때 코드의 허점과 구조적인 한계가 많이 드러나는 문제를 경험했습니다.
그래서 이번에는 테스트를 중심으로 개발 흐름을 잡으며,
코드의 안정성과 완성도를 높이는 데 집중했습니다.

**[ 신경 쓴 코드 설계 ]**

클래스 내부에서는 #을 사용하여 private 변수를 선언하고,
getter/setter 메서드를 활용해 정보 은닉을 강화했습니다.

또한 View는 지난 과제에서 입력과 출력을 하나의 클래스에서 처리했지만,
이번에는 InputView와 OutputView로 분리하여 각자의 역할을 명확히 구분했습니다.

마지막으로, 클래스 설계 시에는 실제 로또 구매 과정을 모델링하려 노력했습니다.

로또 판매점에서 번호를 자동으로 생성하는 기계 → LottoGenerator

추첨된 로또 번호를 기반으로 결과를 자동 채점하는 기능 → LottoResultChecker
